# AGENTS.md

Notes for coding agents working on OCR Clip. See README.md for what the app does.

## Layout

Single module, `app/`, package `com.local.ocrclip`. Plain Activities and Views, no Compose, no AndroidX, no XML layouts (the settings screen is built in code). The only resource XML besides the accessibility config is the stroke icons in `res/drawable/ic_*.xml`. Keep it that way unless there is a real need.

| File | Role |
|---|---|
| `OcrService.kt` | Accessibility service: key filter for the two hotkeys (lookup and translate), `takeScreenshot`, crop, OCR dispatch, clipboard, dictionary. Also the `com.local.ocrclip.CAPTURE` test broadcast. |
| `LensOcr.kt` | Google Lens OCR via `lensfrontend-pa.googleapis.com/v1/crupload` (owocr's "glens" request). The protobuf is hand-encoded and decoded, with no protobuf dependency. Field numbers come from Chromium's `lens_overlay_*.proto`. |
| `DictionaryOverlay.kt` | `TYPE_ACCESSIBILITY_OVERLAY` WebView over the game. While it's open it takes key focus. The service keeps three: dictionary, translator and the offline lookup page (`showPage`). Only the lookup one gets the `OCRClip` JavaScript bridge, because it never loads a website. Also defines the `Overlay` interface the key filter uses to close whichever window is open. |
| `LocalDictionary.kt` | Offline lookup in `filesDir/dict.db`, the SQLite file `tools/build_dict.py` builds on a PC from Yomitan zips (`SCHEMA_VERSION` must match the script's). Scans like Yomitan: longest substring first (up to 16 characters), NFKC plus both kana scripts, deinflected, then `term IN … OR reading IN …`. Glossaries are raw deflate against a per-dictionary preset (`dictionaries.preset`), so they're only fetched and inflated for the entries shown. `lookup` is the `@JavascriptInterface` the page calls. |
| `Deinflector.kt` | Yomitan's `LanguageTransformer.transform` over `assets/japanese-transforms.json`. That JSON is generated by `tools/export_yomitan_transforms.py` from Yomitan's `japanese-transforms.js` (parsed as text, never run); don't edit it by hand. |
| `LookupPage.kt` | HTML, CSS and JS of the lookup page, and rendering of entries: Yomitan structured content (allow-listed tags, sanitised styles, no images), frequencies and pitch accent. Internal links (`?query=…`) become `data-q` spans the page script looks up in place through `OCRClip.lookupTerm`, with a history stack; other links stay inert. The page reports its history depth with `OCRClip.setHistory`, and while it's above 0 `OcrService` turns B/Back into `back()` instead of closing the overlay. |
| `TranslationPopup.kt` | Compact, non-focusable overlay for DeepL API results, placed at the edge away from the capture region. |
| `DeepL.kt` | DeepL API v2 `/translate` client (keys ending `:fx` use `api-free.deepl.com`). The translate hotkey uses it when `deepl_key` is set and falls back to the translator page on failure. |
| `Prefs.kt` | Everything in SharedPreferences file `settings`. Keys: `hotkey`, `translate_hotkey`, `enabled`, `engine` (`local`/`lens`), `keep_newlines`, `copy_to_clipboard`, `show_toast`, `dictionary_mode` (`off`/`overlay`/`local`/`browser`), `dictionary_url`, `dictionary_order` and `disabled_dictionaries` (local dictionaries by title), `translate_url`, `deepl_key`, `deepl_target`, `last_result`, `region_l/t/r/b`. |
| `MainActivity.kt` | Settings screen, built in code for a 640×456 dp landscape window (Retroid Pocket Nova at 320 dpi): a navigation rail (Capture, Lookup, Translate, Service, plus the hotkeys on/off toggle) and two-column pages of card groups. Each widget adds a refresher that redraws it from `Prefs`; clicks only write prefs and the prefs listener refreshes. It also binds the hotkeys in a dialog, through `OcrService.bindingHotkey`, and loads the dictionary database (file picker, copied to a temp file and validated before it replaces `dict.db`). |
| `Ui.kt` | Building blocks for the settings screen: `Palette` (Material 3 dark roles on pure black, from the wallpaper palette on Android 12+), card and button backgrounds with a ripple and a D-pad focus ring, the drawn switch/radio/checkbox (`Indicator`) and the capture region thumbnail (`RegionPreview`). |
| `RegionActivity.kt` | Drag a capture region over the last screenshot, stored as fractions of the screen. |
| `ServiceEnabler.kt` | Re-adds the service to `enabled_accessibility_services` using `WRITE_SECURE_SETTINGS`. `BootReceiver` runs on boot or update and re-checks at 30 s, 2 min and 5 min, because Retroid firmware resets the list on boot. |

`tools/` holds the PC-side scripts (Python 3, standard library only): `build_dict.py` (Yomitan zips → `dict.db`) and `export_yomitan_transforms.py` (Yomitan rules → `japanese-transforms.json`).

The project is GPL-3.0-or-later (`LICENSE`) because it includes Yomitan's deinflection rules.

## Build

```sh
JAVA_HOME=/usr/lib/jvm/java-17-openjdk ./gradlew assembleDebug
```

AGP 9.x, Gradle 9.x, compileSdk/targetSdk 36, minSdk 30 (needed for `AccessibilityService.takeScreenshot`), arm64-v8a only. Output: `app/build/outputs/apk/debug/app-debug.apk`. There are no tests; verify on a device.

## CI and releases

`.github/workflows/build.yml` builds the debug APK on every push to `main` and uploads it as an Actions artifact. A pushed `v*` tag also creates a GitHub release with the APK attached. The workflow signs with the debug keystore the owner's local Gradle uses, `~/.config/.android/debug.keystore` (`XDG_CONFIG_HOME` is set, so not `~/.android/`), stored base64-encoded in the repo secret `DEBUG_KEYSTORE_BASE64`. That way CI builds install over locally built ones; a different key would force an uninstall, which wipes settings and the `WRITE_SECURE_SETTINGS` grant.

To release: bump `versionCode` and `versionName` in `app/build.gradle.kts`, commit, then `git tag vX.Y && git push origin main vX.Y`. The tag must match `versionName`.

## Testing on a device

- `adb shell input keyevent` **bypasses** accessibility key filters, so it can't trigger the hotkey. Use `adb shell am broadcast -a com.local.ocrclip.CAPTURE` instead (add `--es action translate` for the translate path). The receiver is DUMP-protected: adb shell can send it, normal apps can't.
- It's a debug build, so `run-as` works. Read the result with `adb shell run-as com.local.ocrclip cat shared_prefs/settings.xml` (`last_result`).
- To preload settings, force-stop the app, then copy a prefs XML in with `run-as com.local.ocrclip sh -c "mkdir -p shared_prefs && cp /data/local/tmp/x.xml shared_prefs/settings.xml"`.
- To edit a settings field over adb, open the app, scroll with `input swipe 640 800 640 100` (the Nova is landscape, 1280×960), find the field's bounds with `uiautomator dump`, tap it, then `input keycombination 113 29` (Ctrl+A) and `input text '<value>'`. Don't clear fields with `KEYCODE_DEL` on the Retroid: it inserted stray text instead.
- Don't toggle the accessibility service on someone's device without asking. Opening the app re-enables it through `ServiceEnabler`.
- Retroid devices kill background processes in standby. The app can end up force-stopped, so `BOOT_COMPLETED` and `MY_PACKAGE_REPLACED` may not arrive. Opening the app fixes it.

## Conventions

- Kotlin, 4-space indent, ~120-column lines. Comments are sparse and explain *why*, not what.
- Text is Japanese. `OcrService.format` joins lines without separators and removes stray spaces between CJK characters.
- UI strings are inline in code or the layout, not in `strings.xml`, except the app and service labels.
- The service must never read or store screen content except when a hotkey is pressed. Keep `service_description` in `strings.xml` accurate if that changes.
