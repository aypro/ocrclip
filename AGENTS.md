# AGENTS.md

Notes for coding agents working on OCR Clip. See README.md for what the app does.

## Layout

Two apps share one repo: the Android app and the Linux desktop app in `desktop/` (see [Desktop](#desktop-desktop)). What both use lives in `shared/`: the lookup page's `lookup.css` and `lookup.js`, and `japanese-transforms.json`. The Android app packs `shared/` as assets (`assets.srcDir("../shared")` in `app/build.gradle.kts`); the desktop app reads it from the repo, or from its own copy in a release.

The Android app is a single module, `app/`, package `com.local.ocrclip`, plus one native library (`app/src/main/cpp`, llama.cpp from the `third_party/llama.cpp` submodule) for offline translation. Plain Activities and Views, no Compose, no AndroidX, no XML layouts (the settings screen is built in code). The only resource XML besides the accessibility config is the stroke icons in `res/drawable/ic_*.xml`. Keep it that way unless there is a real need.

| File | Role |
|---|---|
| `OcrService.kt` | Accessibility service: key filter for the two hotkeys (lookup and translate), `takeScreenshot`, crop, OCR dispatch (Lens falls back to ML Kit when there's no network or Lens can't be reached; then DeepL is skipped too and the popup note says so), clipboard, dictionary. Also the `com.local.ocrclip.CAPTURE` test broadcast. |
| `LensOcr.kt` | Google Lens OCR via `lensfrontend-pa.googleapis.com/v1/crupload` (owocr's "glens" request). The protobuf is hand-encoded and decoded, with no protobuf dependency. Field numbers come from Chromium's `lens_overlay_*.proto`. |
| `DictionaryOverlay.kt` | `TYPE_ACCESSIBILITY_OVERLAY` WebView over the game. While it's open it takes key focus. The service keeps three: dictionary, translator and the offline lookup page (`showPage`). Only the lookup one gets the `OCRClip` JavaScript bridge, because it never loads a website. Its page loads at `https://ocrclip.invalid/`, and requests there are served from local files (`/font` → `Prefs.lookupFont`, the picked file in `filesDir/fonts/`). Also defines the `Overlay` interface the key filter uses to close whichever window is open. With `panel` it fills a second screen: `FLAG_NOT_FOCUSABLE`, explicit display-sized window, a native ✕ (`closeChip`). |
| `LocalDictionary.kt` | Offline lookup in `filesDir/dict.db`, the SQLite file `tools/build_dict.py` builds on a PC from Yomitan zips (`SCHEMA_VERSION` must match the script's). Scans like Yomitan: longest substring first (up to 16 characters) of the run of Japanese from the offset (`isJapanese`: kana, kanji, ー, full-width letters and digits; anything else ends the scan, and a lookup starting on it skips the database), NFKC plus both kana scripts, deinflected, then `term IN … OR reading IN …`. Glossaries are raw deflate against a per-dictionary preset (`dictionaries.preset`), so they're only fetched and inflated for the entries shown. `lookup` is the `@JavascriptInterface` the page calls. Schema 3 adds `dictionaries.styles` (each zip's styles.css); schema 2 still opens, without styles. It keeps the result shown, so `addToAnki(entry, definition, sense, offset)` from a + button resolves the indices (a sense ≥ 0 trims the definition with `LookupPage.onlySense`) and calls the `anki` callback `OcrService` sets while Anki is set up; the bridge answers with JSON (`error`, or `notice` for a note added without audio). |
| `Deinflector.kt` | Yomitan's `LanguageTransformer.transform` over `shared/japanese-transforms.json` (an asset). That JSON is generated by `tools/export_yomitan_transforms.py` from Yomitan's `japanese-transforms.js` (parsed as text, never run); don't edit it by hand. |
| `LookupPage.kt` | The lookup page (its CSS and script are `shared/lookup.css` and `shared/lookup.js`, read from assets once), and rendering of entries: Yomitan structured content (allow-listed tags, sanitised styles, no images), frequencies and pitch accent. The page is `lang="ja"` so CJK fonts draw Japanese glyphs, not the Chinese ones the en-US system locale picks; a loaded font covers only kana, kanji and full-width forms. Internal links (`?query=…`) become `data-q` spans the page script looks up in place through `OCRClip.lookupTerm`, with a history stack; other links stay inert. A tap on other Japanese text in the results is followed the same way: `scanAt` reads from the tapped character (`caretRangeFromPoint`, the run of Japanese up to 16 characters across inline elements, skipping `rt`/`rp`; its `JAPANESE` regex matches `isJapanese`) and `lookupTerm` finds the longest match. The page reports its history depth with `OCRClip.setHistory`, and while it's above 0 `OcrService` turns B/Back into `back()` instead of closing the overlay. With Anki set up each definition gets a + button, and so does each sense of a definition with several (`senseCount`): Jitendex's `data-content="sense"` elements and 新和英's numbered lines (`senseLines`). `ankiGlossary(single = true)` writes MainDefinition without the numbered list, dictionary name and tags; plain text gets `<br>` for its newlines. `ankiGlossary` renders definitions the way Yomitan writes them into Anki (gloss-sc-* classes, data-sc-* attributes, `yomitan-glossary` wrapper) and `scopeCss` prefixes each dictionary's styles.css with `.yomitan-glossary [data-dictionary="…"]`. |
| `Anki.kt` | AnkiDroid's content provider API (`content://com.ichi2.anki.flashcards`), written against `FlashCardsContract`/`AddContentApi` without the library: models, decks, media insert (`file_uri` + `preferred_name`), and notes through `bulkInsert` with `?deckId=` (a single insert ignores the deck). Needs the runtime permission `com.ichi2.anki.permission.READ_WRITE_DATABASE`. |
| `AnkiNote.kt` | Field values by field name, following Yomitan's Lapis setup (Expression, ExpressionFurigana, ExpressionReading, MainDefinition, Glossary, Sentence, Picture, PitchPosition, Frequency, FreqSort, and ExpressionAudio as `[sound:…]`) plus a few common aliases. Furigana split per kanji run like Yomitan's furigana-plain; FreqSort is the harmonic mean rank (9999999 without frequencies). |
| `LocalAudio.kt` | Word recordings for Anki notes, read from `noBackupFilesDir/audio.db`: the `android.db` that the Anki add-on Local Audio Server for Yomichan generates (tables `entries(expression, reading, source, speaker, display, file)` and `android(file, source, data)`). `find` matches the term, then the reading with katakana folded to hiragana and takes the first source in the add-on's order; rows without a reading (Forvo) match any and come last. Opened per call. |
| `ShareProvider.kt` | Non-exported provider that serves the lookup's screenshot (`cacheDir/lookup_screenshot.jpg`, as `image/jpeg`) and the word's recording (`cacheDir/lookup_audio.<ext>` at `/audio.<ext>`, as `audio/ogg` or `audio/mpeg`) to AnkiDroid through a per-URI read grant. AnkiDroid names the stored file from the type. |
| `TranslationPopup.kt` | Compact, non-focusable overlay for translations (DeepL, or the offline model's streamed in, with a note line saying so), placed at the edge away from the capture region (at the top, with a ✕, on a second screen). |
| `Notice.kt` | Small non-focusable, non-touchable overlay that shows a failure ("No text found", Lens or DeepL errors) for 3 s. Used instead of a toast, which Android drops while the app's notifications are off. The next capture hides it and waits 100 ms so it isn't read as text. |
| `DeepL.kt` | DeepL API v2 `/translate` client (keys ending `:fx` use `api-free.deepl.com`). The translate hotkey uses it when `translate_engine` is `deepl` and `deepl_key` is set. On failure it falls back to the offline model if one is loaded, otherwise to the translator page. |
| `LocalTranslator.kt` | Offline Japanese → English with a CAT-Translate GGUF (`noBackupFilesDir/translate.gguf`) through `libllm.so`. The prompt is CAT-Translate's chat format written out (`<|user|>…</s><|assistant|>`); `validate` reads only the GGUF's chat template to reject other models. One thread: loads on first use (about 2 s for the 3.3B), streams greedy output to a callback that can stop it, frees the model after 10 idle minutes. `libllm.so` targets `armv8.2-a+dotprod+fp16`, so it's only loaded where `/proc/cpuinfo` lists `asimddp` (`supported`). |
| `cpp/llm.cpp`, `cpp/CMakeLists.txt` | The JNI side: load, free, read the chat template, and generate with `llama_process`, passing UTF-8 byte arrays (JNI's modified UTF-8 breaks characters outside the BMP) and emitting only complete UTF-8 sequences. CMake builds llama.cpp statically with -O3 even in debug builds (at -O0 a translation takes minutes). |
| `Prefs.kt` | Everything in SharedPreferences file `settings`. Keys: `hotkey`, `translate_hotkey`, `enabled`, `engine` (`local`/`lens`), `keep_newlines`, `copy_to_clipboard`, `show_toast`, `dictionary_mode` (`off`/`overlay`/`local`; an old `browser` value reads as `overlay`), `dictionary_url`, `dictionary_order` and `disabled_dictionaries` (local dictionaries by title), `translate_url`, `translate_engine` (`deepl`/`offline`), `translate_model_name` (the loaded model's file name, only shown), `deepl_key`, `deepl_target`, `lookup_font` (name of the picked font, a file in `filesDir/fonts/` named after the font; empty = system font), `anki_model`/`anki_model_name`, `anki_deck`/`anki_deck_name` (-1 = Default deck), `anki_tags`, `second_screen`, `last_result`, `region_l/t/r/b`. |
| `MainActivity.kt` | Settings screen, built in code for a 640×456 dp landscape window (Retroid Pocket Nova at 320 dpi): a navigation rail (Capture, Lookup, Translate, Service, plus the hotkeys on/off toggle) and two-column pages of card groups. The Lookup page's Anki section asks for AnkiDroid's permission and picks the note type (Lapis+ preselected) and deck with the shared `choose` list dialog; its Word audio row loads the audio database (`importAudio`, progress and failures shown in the row, state kept in the companion so it outlives the activity). Each widget adds a refresher that redraws it from `Prefs`; clicks only write prefs and the prefs listener refreshes. It also binds the hotkeys in a dialog, through `OcrService.bindingHotkey`, and loads the dictionary database (file picker, copied to a temp file and validated before it replaces `dict.db`). |
| `Ui.kt` | Building blocks for the settings screen: `Palette` (Material 3 dark roles on pure black, from the wallpaper palette on Android 12+), card and button backgrounds with a ripple and a D-pad focus ring, the drawn switch/radio/checkbox (`Indicator`) and the capture region thumbnail (`RegionPreview`). |
| `RegionActivity.kt` | Drag a capture region over the last screenshot, stored as fractions of the screen. |
| `ServiceEnabler.kt` | Re-adds the service to `enabled_accessibility_services` using `WRITE_SECURE_SETTINGS`. `BootReceiver` runs on boot or update and re-checks at 30 s, 2 min and 5 min, because Retroid firmware resets the list on boot. |

`tools/` holds the PC-side scripts (Python 3, standard library only): `build_dict.py` (Yomitan zips → `dict.db`), `strip_jitendex.py` and `strip_shinwaei.py` (zip → trimmed zip: Jitendex without examples and attribution links, 新和英 without romaji tags), `split_jmnedict.py` (JMnedict + a frequency zip → JMnedict with common readings listed first, highlighted, and the top one set as the entry's reading) and `export_yomitan_transforms.py` (Yomitan rules → `japanese-transforms.json`).

The project is GPL-3.0-or-later (`LICENSE`) because it includes Yomitan's deinflection rules.

### Desktop (`desktop/`)

A Python 3 + PyQt6/Qt WebEngine port for a Linux desktop (Omarchy/Hyprland), triggered by new files in a screenshots folder instead of a hotkey. System Python and system PyQt6 only, standard library otherwise; no venv. Run `desktop/ocrclip-desktop`; settings in `~/.config/ocrclip/settings.json` (Prefs' keys where they apply). `lookup_page.py` and `deinflector.py` read `shared/` through `config.SHARED`: `ocrclip_desktop/shared/` in a release tarball, the repo's `shared/` in a checkout. The version is `__version__` in `desktop/ocrclip_desktop/__init__.py`. When `LookupPage.kt`'s rendering (`results`, structured content, senses, `ankiGlossary`, `scopeCss`) or `LocalDictionary`/`AnkiNote` logic changes, port the change to the matching Python module.

| File | Role |
|---|---|
| `app.py` | `App`: `inotifywait` (close_write, moved_to) on `watch_dir` → crop (`region`, not for `crop_skip` names) → Lens, or the offline worker when Lens is unreachable or `engine` is `local` → `format_lines` (`OcrService.format`) → `wl-copy` → lookup window and translation (DeepL, offline model, or the translator link; same notes as the popup). A newer screenshot makes older results go unused (`request`). After a card is added, `App` syncs Anki (`SYNC_DELAY` after the last card, at most every `SYNC_INTERVAL`, `anki_sync` turns it off); a sync that times out is most likely Anki's full-sync dialog waiting unseen, and the notification says so. Tray menu, `QLocalServer` commands (`once`, `toggle`, `show`, `hide`, `region`, `quit`), Anki note assembly. Failures go to `notify-send`. |
| `window.py` | The lookup window (`QWebEngineView`, Wayland app id `ocrclip`) and `Bridge`, the `ocrclip://` scheme handler: `/page` is the page, `/api/<method>?q=<json>` are the `OCRClip` calls, answered synchronously because the page's shim uses sync XHR (QWebChannel is async-only and would need the shared script rewritten). Offsets from the page are UTF-16 and converted (`utf16_to_index`). |
| `lookup_page.py`, `dictionary.py`, `deinflector.py`, `anki_note.py`, `deepl.py`, `lens.py` | Ports of `LookupPage.kt`, `LocalDictionary.kt`, `Deinflector.kt`, `AnkiNote.kt`, `DeepL.kt`, `LensOcr.kt`. The page gets a `#translation` strip and the `OCRClip` shim on top of the shared script. |
| `anki.py` | AnkiConnect (`findNotes`/`notesInfo` for the ✓ marks, `storeMediaFile`, `addNote` with duplicates allowed since the page confirms them, `sync`, which answers only when Anki's sync is done) and word audio from the Local Audio Server add-on's HTTP API (first source). |
| `offline_ocr.py`, `ocr_worker.py` | meikiocr in a worker process under another interpreter (`offline_ocr_python`, default the owocr uv tool's Python with meikiocr added), JSON lines over stdin/stdout, stopped after 10 idle minutes. `ocr_worker.py` must not import from the package. |
| `translate.py` | `llama-server` (`llama_server`, `translate_model`) as a child process on a free port, started on first use, checked like `LocalTranslator.validate` via `/props`, streamed from `/completion` with the same prompt, stopped after 10 idle minutes. |
| `region.py` | Region picker over the last screenshot. |

Testing: run with `--offline` to skip Lens and DeepL. Point `watch_dir` at a scratch folder and `cp` screenshots in, or `ocrclip-desktop once <file>`. There are no tests.

## Build

```sh
git submodule update --init  # third_party/llama.cpp, once after cloning
JAVA_HOME=/usr/lib/jvm/java-17-openjdk ./gradlew assembleDebug
```

AGP 9.x, Gradle 9.x, compileSdk/targetSdk 36, minSdk 30 (needed for `AccessibilityService.takeScreenshot`), arm64-v8a only, NDK 29.0.14206865 and CMake 3.31.6 from the SDK for `libllm.so`. The llama.cpp submodule is pinned to the commit the offline translation was benchmarked with; test speed on a device before moving it. Output: `app/build/outputs/apk/debug/app-debug.apk`. There are no tests; verify on a device.

## CI and releases

Each app has its own workflow and its own release tags, so they're built and released independently. GitHub ignores `paths` for tag pushes, so a tag always builds; each release's notes start from the previous tag of its own series.

- `.github/workflows/android.yml` builds the debug APK on pushes to `main` that change `app/`, `shared/`, `third_party/` or the Gradle files, and uploads it as an Actions artifact. A pushed `v*` tag also creates a GitHub release "Android vX.Y" with the APK attached.
- `.github/workflows/linux.yml` checks the desktop app (byte-compiles it and runs the deinflector and page against `shared/`, no Qt needed) on pushes to `main` that change `desktop/` or `shared/`, and builds `ocrclip-desktop-<version>.tar.gz` (the package with `shared/` copied into it, the launcher, the service file, README and LICENSE). A pushed `desktop-v*` tag also creates a release "Linux vX.Y" with the tarball. `v*` doesn't match `desktop-v*`, so neither tag starts the other workflow.

The Android workflow signs with the debug keystore the owner's local Gradle uses, `~/.config/.android/debug.keystore` (`XDG_CONFIG_HOME` is set, so not `~/.android/`), stored base64-encoded in the repo secret `DEBUG_KEYSTORE_BASE64`. That way CI builds install over locally built ones; a different key would force an uninstall, which wipes settings and the `WRITE_SECURE_SETTINGS` grant.

To release Android: bump `versionCode` and `versionName` in `app/build.gradle.kts`, commit, then `git tag vX.Y && git push origin main vX.Y`. The tag must match `versionName`.

To release Linux: bump `__version__` in `desktop/ocrclip_desktop/__init__.py`, commit, then `git tag desktop-v<version> && git push origin main desktop-v<version>` (e.g. `desktop-v0.1`). The workflow fails if the tag doesn't match `__version__`.

## Testing on a device

- `adb shell input keyevent` **bypasses** accessibility key filters, so it can't trigger the hotkey. Use `adb shell am broadcast -a com.local.ocrclip.CAPTURE` instead (add `--es action translate` for the translate path). The receiver is DUMP-protected: adb shell can send it, normal apps can't.
- It's a debug build, so `run-as` works. Read the result with `adb shell run-as com.local.ocrclip cat shared_prefs/settings.xml` (`last_result`).
- To preload settings, force-stop the app, then copy a prefs XML in with `run-as com.local.ocrclip sh -c "mkdir -p shared_prefs && cp /data/local/tmp/x.xml shared_prefs/settings.xml"`.
- To edit a settings field over adb, open the app, scroll with `input swipe 640 800 640 100` (the Nova is landscape, 1280×960), find the field's bounds with `uiautomator dump`, tap it, then `input keycombination 113 29` (Ctrl+A) and `input text '<value>'`. Don't clear fields with `KEYCODE_DEL` on the Retroid: it inserted stray text instead.
- To load a translation model without the file picker, push the GGUF to `/data/local/tmp` and `run-as com.local.ocrclip cp` it to `no_backup/translate.gguf` (the settings row then shows only its size). To test the fallbacks, `svc wifi disable` (adb stays up over USB): Lens and DeepL are both skipped and the popup reads "No connection · On-device OCR · Offline translation". Ask before toggling Wi-Fi on someone's device.
- Don't toggle the accessibility service on someone's device without asking. Opening the app re-enables it through `ServiceEnabler`.
- Retroid devices kill background processes in standby. The app can end up force-stopped, so `BOOT_COMPLETED` and `MY_PACKAGE_REPLACED` may not arrive. Opening the app fixes it.

## Conventions

- Kotlin, 4-space indent, ~120-column lines. Comments are sparse and explain *why*, not what.
- Text is Japanese. `OcrService.format` joins lines without separators and removes stray spaces between CJK characters.
- UI strings are inline in code or the layout, not in `strings.xml`, except the app and service labels.
- The service must never read or store screen content except when a hotkey is pressed. Keep `service_description` in `strings.xml` accurate if that changes.

## Second screen

`OcrService.Screen` holds one set of overlays per screen: `game`, and `panel` while `second_screen` is on and a `DISPLAY_CATEGORY_PRESENTATION` display is attached (set up on service start, display added and pref change; dropped on display removed). Only the game set takes keys, so only it closes on B/Back/hotkey. The panel keeps a black non-focusable window under its pages, because Android mirrors the default display onto an empty one (and routes the add-on's touches to it); tapping it clears the panel.

Gotcha: `AccessibilityService.createDisplayContext(display)` keeps the default display's configuration (1280x960 window bounds on the Nova). Views built with it lay out, scroll and clip to that size. Windows are added through that context's WindowManager, the only one with the accessibility overlay token for the display, but views are built with `createWindowContext(TYPE_ACCESSIBILITY_OVERLAY, null)` of it, which has the display's real configuration (nothing is added through that one), and panel windows get explicit sizes from `displaySize()`. Test on the add-on with `adb shell input -d <id> tap` and `screencap -d <SurfaceFlinger id>`; the display id changes on every replug.
